# Integrate the bounded solid-contact correction

Full engineering loop. Internal draft-branch integration only; production and complete-replica claims remain gated by the full task evidence.

## Selected scope and tradeoff

The original f32 Rapier.js v0.19.2 wrapper with the Parry 0.25.1 SAT/cache correction passes 198 reference-frame contact trials, 16 cached-contact tie cases, 1200 randomized primitive/hull pairs in both orders, 360 near-parallel cases and 36 dynamic closed shells at the original settings. Independent review finds no remaining correctness findings in the narrow patch. Two clean builds with pinned Rust 1.98.1 and wasm-bindgen 0.2.100 produce identical CJS/MJS/WASM/lock hashes. Alternative precision-only, surface mesh, newer upstream and native-frame hinge experiments do not justify adoption. Keep the original joints and scalar precision.

Proposal: maintain this small source patch and a reproducibly built local package for the headless verifier. This costs an owned upstream patch and a ~2.2 MB generated CJS runtime. It is justified provisionally by a reproducible false-deep-contact defect, controls that fail without the patch, and a corrected solid collision matrix. Neither a desired source pass nor an increased solver budget selects this backend. A future official dependency can replace it only after the same gates pass.

## Integration boundary

- Add a local `@magnatiles/rapier-contact` package containing the unchanged JS wrapper declarations, one CJS entry shared by both import and require, the generated runtime, upstream licenses, exact source patch, lockfiles and build recipe/provenance. No install-time compilation or network fetch. Original Rapier remains available for the explicitly separate browser sandbox and regression controls.
- Route headless engine/planner/replication imports through one `lib/engine/physics-backend.ts`. Export only used safe constructors/enums/types and init plus a guarded World. World creation accepts gravity only, not raw subsystem arguments. Reject descriptors/shape objects from another backend, bodies from another world, and foreign raw-shaped arguments before calling WASM. Guard the creation/removal paths used by this app; no generic plugin registry or backend selector.
- Disable binary snapshot save/restore through the adapter. Preserve the existing explicit EngineState handoff; add a new identity encoding the exact backend artifact, precision, wrapper ABI and unchanged numerical profile. Old JSON states and prepared workspaces fail existing identity checks; source/report hashes must cover the adapter/vendor runtime. No legacy state migration earns acceptance.
- Record and compare every exposed world integration setting against the unpatched same-source control. Commit the full native integration/activation snapshot and identical source evidence for hidden defaults. Runtime settings are asserted at world construction, then the app still explicitly uses 16 iterations, 120 Hz contact frequency and <=1/960 second collision steps. Original f32 precision remains at every physical array boundary.

## Reproducibility and proof

Build from the exact rapier.js commit and original Parry crate archive, verify source hashes before applying the patch, pin the Rust/wasm/Node packaging dependencies with locks, and preserve all licenses. Build in a documented deterministic path or normalize build paths; compare two fresh build outputs. The committed runtime must match the proven hash. No unrelated Rust or JS behavior change, hinge extension, settings mutation, collision filtering or artificial force is permitted.

Required tests: original unpatched false-contact negative control; corrected geometry/mass/COM/full inertia; random/cached/near-parallel and dynamic contact tests; foreign descriptor/shape/world/raw rejection without WASM panic; repeated create/dispose and CJS/ESM singleton behavior; stale JSON and binary snapshot rejection; full physical/assembly/planner/fault suite and structural benchmark. Keep the continuous solid guard and propagate failures through every result/report. Record full source construction outcomes separately from nominal release and functional cars. Rebuild current evidence, review code, run full test/type/lint/build checks and browser QA, then update draft PR with exact-head preview checks. Do not claim reliable replicas or promote production from these integration tests alone.

## Integration review resolution

All three concrete requirements in `runs/reviews/contact-backend-integration-plan-review.txt` are accepted. The adapter retains the existing World method surface by subclassing the selected wrapper: create/remove bodies, colliders and impulse joints; contactPair; body/collider/joint access; mutable gravity and integration settings; step and free. Guards cover app ingress rather than replacing that surface with an abstract framework. Tests exercise roll, cars, actual contacts and altered fixture settings through it.

The exact identity field remains `EngineState.physicsModel`; `PHYSICS_MODEL_VERSION` incorporates the selected CJS artifact hash, f32 precision, Rapier.js/Rust/Parry versions, adapter ABI 1 and a numerical-profile hash. `validateContinuation` in rapier-world and `validatePreparedWorkspace` in workspace must compare that same full string. Binary snapshots are disabled. Tests alter each identity component and reject both continued states and prepared workspaces. Existing source-report model IDs include the same constant. `validationCodeHash()` will recursively hash the entire explicit `vendor/rapier-contact` package, including runtime, declarations, metadata, patch, recipe, locks and provenance. Packaging never silently inherits coverage from package-lock alone.
