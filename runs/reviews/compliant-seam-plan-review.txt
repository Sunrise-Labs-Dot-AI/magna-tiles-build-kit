**CRITICAL: Angular momentum coupon can pass without testing spin inertia**
File: [runs/2026-09-28-compliant-seam-plan.md](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/runs/2026-09-28-compliant-seam-plan.md:20)

Scenario: an off-centre spring applies equal/opposite point impulses but the implementation computes angular momentum only as `r x mv`, or uses bodies with infinite/zero angular inertia. The coupon can report conserved angular momentum while missing a wrong spin impulse. Rapier exposes `worldCom`, `principalInertia`, `principalInertiaLocalFrame`, and `effectiveAngularInertia`, so the test must include spin angular momentum.

Fix: require explicit finite mass properties for both free bodies and compute total angular momentum as orbital plus spin: `sum((com - origin) x m*v_com + I_world * omega)`. Predeclare absolute and relative tolerances for linear momentum, angular momentum, and body/edge reversal invariance.

**CRITICAL: Numeric momentum and invariance tolerances are missing**

Scenario: “within declared numerical bounds” is promised but no bounds are actually declared for total momentum or order/frame invariance. A later implementation could choose bounds after seeing failures, or use broad tolerances that hide solver asymmetry.

Fix: before execution, declare concrete tolerances for linear momentum, angular momentum, force/wrench equality under body order reversal, edge order reversal, global rotation, and global translation. Use both absolute floors and relative tolerances because near-zero conserved quantities make pure relative checks unstable.

**WARNING: Break force units are ambiguous after native conversion**
File: [runs/2026-09-28-compliant-seam-plan.md](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/runs/2026-09-28-compliant-seam-plan.md:11)

Scenario: the plan converts each point spring to native inch/kg/s constants, then says the break sum exceeds `5.8 N`. If code sums `k*d + c*v` using native constants and compares directly to `5.8`, the break threshold is off by `39.37007874015748`. Existing constants store `MAGNET_HOLD_FORCE = 5.8` in N-like heuristic units, while native force is kg*in/s².

Fix: state the break calculation unit explicitly. Either compute break force with the original `N/in` and `N/(in/s)` constants and compare to `5.8 N`, or compute native force and compare to `5.8 * ENGINE_UNITS_PER_METER`.
