**Findings**

1. **Seed semantics are underspecified and can be misleading.**  
   [physics-model.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/engine/physics-model.ts:185) seeds no native state; initial imperfections are tile-id deterministic. The only current seed path is `perturbFirstRelease` in [rapier-world.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/engine/rapier-world.ts:333), which changes velocities. The plan says seeds `0/17/53`, “no forces,” and “preserve the actual initial state” at [native-fold-probe-plan.md](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/runs/2026-09-27-native-fold-probe-plan.md:12).  
   **Action:** explicitly choose one: seed rows are intentional identical controls, or the middle body receives the existing release perturbation and the protocol records pre/post velocities and treats that as part of the diagnostic.

2. **The current `simulateHeldMotion` API cannot express this connected two-end-grip fold.**  
   `simulateHeldMotion` requires exactly one grip on the moving set and rejects existing joins crossing moving/non-moving sets in [held-motion.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/replication/held-motion.ts:45) and [held-motion.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/replication/held-motion.ts:69). For a three-panel strip, any moving-set choice either has two moving grips or an old hinge crossing the moving boundary.  
   **Action:** the plan should state the probe must use a bespoke off-path `createEngineWorld` loop, not `simulateHeldMotion`, and must assert per step that body modes are exactly root `Fixed`, middle `Dynamic`, terminal `KinematicPositionBased`.

3. **The standing-displacement check can accidentally measure prescribed motion as failure.**  
   Current engine displacement targets are initialized to the starting pose in [rapier-world.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/engine/rapier-world.ts:321), and `maxDisplacement()` compares actual bodies to those stored targets in [rapier-world.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/engine/rapier-world.ts:238). A terminal panel commanded through a 120 degree fold would exceed that unless targets are updated or bypassed.  
   **Action:** require an explicit per-panel articulated-target residual, computed outside `engine.maxDisplacement()` unless the probe deliberately updates `targetPosition/targetRotation` every step. This is necessary to distinguish solver deviation from the prescribed geometry.

4. **“Actual hinge-frame use” is still ambiguous.**  
   Initial joints are created from one shared point and `fromEdge.direction` in [physics-model.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/engine/physics-model.ts:201), then installed as Rapier revolute joints in [rapier-world.ts](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/lib/engine/rapier-world.ts:341). `secondAnchors` only appear for localized new joints, not the initial model path. The plan says derive “two world hinge axes and anchors” at [native-fold-probe-plan.md](/Users/jamesheath/Documents/Claude/Projects/Worktrees/magnatiles-footage-replicas/runs/2026-09-27-native-fold-probe-plan.md:14), but does not require recording the live joint type, anchor fields, axis fields, or whether the distal hinge target frame moves with the middle panel.  
   **Action:** require trace fields for each joint: `id`, `from/to`, `fromLocalAnchor`, `toLocalAnchor`, `axis`, `secondAnchors` presence, limit values, and the derived world anchor/axis at step 0. Also state the distal target hinge is transformed by the articulated middle pose when composing the ideal target.

Everything else I checked is directionally sound: source audit and geometric diagnostic are properly bounded, the plan avoids closure/release overclaims, preserves collision/numerical settings in intent, and requires exact terminal contact inspection rather than inferring closure from command completion.
