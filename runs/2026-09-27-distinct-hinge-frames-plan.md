# Native hinges between distinct immutable body frames

Full engineering loop. This is a separate, bounded diagnostic proposal after the f64 precision-only prototype. Do not change application dependencies or accepted evidence before review and independent verification. Keep PR #4 draft.

## Evidence and hypothesis

The original-kernel f64 prototype passes 198 contact cases, the 72-case flat/loaded frequency sweep, and all 108 closed-shell cases (three independent shells, baked/mixed frames, 960/1920 Hz, 16/32/64 iterations, three seeds). Two clean builds produce identical CJS, MJS, WASM, manifest and lockfile hashes. These results do not justify increasing solver iterations. The actual nine-panel captured release still fails rest at 16, and fresh construction fails a continuous solid-overlap check while inserting the fifth wedge panel in seed 53.

Current continued-frame hinges use two spherical joints one inch apart because the stock JS revolute constructor accepts only one axis expressed in both bodies' local frames. This represents one free rotational degree of freedom but introduces a redundant scalar constraint. Proposal/hypothesis: exposing the existing Rust GenericJointBuilder's independent local frames can encode a native five-constraint revolute joint and remove that redundancy without moving any body or magnetic anchor. This might improve constraint behavior; success is not assumed.

## Bounded implementation and independent acceptance

1. Preserve the audited precision-only prototype and hashes. In a separate /tmp source copy, add one explicit `revoluteFrames(anchor1, frame1, anchor2, frame2)` wrapper constructor. Use the existing Rust `GenericJointBuilder` with `LOCKED_REVOLUTE_AXES`, full local frames and anchors. No motor, damping, mass, material, contact filtering, solver setting, geometry or force-law change. Validate finite unit rotations/anchors at the adapter boundary. Existing API behavior remains unchanged.
2. For a new seam, construct one deterministic proper world frame whose x axis is the seam. Transform the same frame and its physical anchors into each body's immutable frame. Store both local frames, and never recompute them during continuation. A full free rotation range remains free; preserve contacts and break-distance/force checks at the seam and a second witness one inch along it. One native joint replaces the two spherical constraints only in the isolated probe.
3. Before any source replay, independently verify equal world anchor positions and world hinge axes, one free angular degree, rejection of orthogonal angular/linear motion, and continued versus fresh pose trajectories for noncommuting frames. Exercise 0, near-pi and arbitrary rotations. Unsupported hinged panels must fall rather than become stiff or powered. Test deliberate separation/breaking and retained anchors across snapshots. Compare world mass/COM/inertia and settings with the precision-only prototype.
4. Run the independent contact matrix and mixed-frame closed shells at the unchanged 16 iterations and 960 Hz, plus timestep convergence and negative controls. Keep continuous solid guards active. Only after those independent checks, diagnose the captured source release and run fresh construction from the first placement for all seeds. A captured state migrated for diagnosis never earns acceptance.
5. If the native-frame probe gives no benefit or changes physical freedom, reject it. If selected later, extend the f64 backend promotion checklist with a distinct wrapper ABI/model identifier and state rejection; preserve precision-only versus hinge-change evidence separately. Audit/review the final wrapper and adapter diff before vendoring. No production or complete-replica claim from this experiment.

Maintenance decision remains open: a small wrapper extension is more code to own, but accurately expressing existing Rust joints could remove application-level constraints and their special cases. The acceptance evidence must decide; a desired source pass cannot.

## Review and changed prerequisite

`runs/reviews/distinct-hinge-frames-plan-review.txt` clears an isolated prototype only. Before any promotion it requires an explicit joint-kind/frame schema and ABI, separate break witnesses, free angular wrap tests, hard state rejection, and fresh construction. These controls are accepted. No hinge code is implemented yet: the end-to-end f64 hull-array check exposed 18/198 contact failures, so contact diagnosis takes precedence. The initial 198/198 figure above used f32-quantized inputs and is not sufficient precision-only evidence.

The separate polyhedral-normal prototype now passes the independent contact, randomized solid-pair, near-parallel, loaded-frequency and closed-shell checks in the original f32 backend. Actual free release still jitters with two spherical constraints. Resume this bounded native-frame experiment on a separate copy of that f32 SAT backend, preserving the SAT-only runtime and evidence. Give the wrapper, runtime imports and shadow EngineState a distinct native-frame prototype identity. Store a native-revolute discriminator and two immutable frame quaternions; a separate break-witness field cannot instantiate a companion constraint. Test full rotations with no limit impulse and retain the original contact/break controls. No f64 migration is now proposed or required.
